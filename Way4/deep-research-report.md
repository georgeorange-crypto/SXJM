### 问题一：定位区域、直径与“直径圆”

**GitHub 完整方案。** 每次 `direction` 观测对应真实方向落入测量值 ±1°，所以几何上不是一条射线，而是一个 **2° 楔形**。多个观测的可行区域是这些楔形对应半平面的交：

\[
K=\bigcap_{i=1}^{n}W_i.
\]

只要按照确定性有界误差理解题意，这种 **set-membership / 可行集定位** 比“把测向误差当高斯噪声，再做最小二乘得到一个点”更严格，因为它不擅自增加题目没有给出的概率分布假设。GitHub 当前文档明确采用 2° 楔形交集，并把定位区域处理为凸多边形。fileciteturn3file0L2-L2

它公开了三种相互核验的直径算法：

\[
D(K)=\max_{x,y\in K}\|x-y\|.
\]

一是凸多边形顶点两两枚举；二是旋转卡壳；三是支撑函数/对踵方向扫描。最新 README 声称三种方法最大相对互校误差为 \(5.6\times 10^{-11}\)。更值得注意的是，他们没有把“直径 ≤40 m”错误地等价成“存在一个半径 20 m 的圆覆盖区域”，而是另外计算 **最小包围圆 MEC**。fileciteturn3file0L2-L2

**CSDN 的集合几何方案**基本得到了同样结论：把 ±1° 扇区转换为两个有向半平面，求交得到凸多边形，直径用旋转卡壳，真正的保证清除指标用 Welzl 最小包围圆；文章甚至直接使用等边三角形说明“直径为 \(D\)”并不意味着一个直径 \(D\) 的圆能覆盖该集合。citeturn17view0

这一点在数学上非常关键。对边长为 \(D\) 的等边三角形，

\[
R_{\min}=\frac{D}{\sqrt3}>\frac D2.
\]

所以“以定位区域直径为直径的圆一定覆盖定位区域”是 **错误命题**。更一般地，平面 Jung 定理给出

\[
R_{\min}\leq \frac{D}{\sqrt3},
\qquad
\frac{2R_{\min}}D\leq \frac{2}{\sqrt3}\approx1.1547.
\]

GitHub 方案进一步给出了一个接近极限的实际可行区域反例：

\[
\frac{2R^*}{D}=1.147,
\]

并做了随机检测点 Monte Carlo：当检测次数 \(n=2,3,4,5\) 时，“直径圆能够覆盖区域”的比例分别约为 **96.6%、86.0%、80.0%、74.2%**。这说明它不是“极端病态情况下才有问题”，随着多次楔形求交形成更丰富的凸多边形，直接使用直径圆反而越来越不可靠。fileciteturn3file0L2-L2

从算法复杂度看，若当前凸多边形有 \(m\) 个顶点，顶点两两枚举是

\[
O(m^2),
\]

而按凸包环序排列后旋转卡壳可以做到

\[
O(m).
\]

标准半平面交本身可做到 \(O(n\log n)\)；但本题单频道观测数通常不大，所以比赛里真正影响运行时间的并不是这部分 CPU 复杂度，而是**机器狗移动距离和 HTTP/检测动作对应的虚拟时间**。这一点也是很多网络题解“在一个 \(m\le10\) 的凸多边形上大谈算法复杂度，却忽略 1 km 移动就是 200 秒”的常见失衡。

还有一类 CSDN/技术站方案停留在“顶点枚举 + 旋转卡壳 + GDOP”的标准几何框架。公开材料总体与上述主线相符，但有些文章会混用“直径圆”“质心附近的 \(D/2\) 半径圆”“最小包围圆”，这三件事并不等价，因此写论文时一定要分开。CSDN 当前较完整的公开文章已经明确改用 MEC≤20 m 作为严格清除证书。citeturn17view0

**结论：问题一目前的网络共识已经相当清楚——“2°楔形交集 + 凸多边形 + 精确直径 + 最小包围圆”是最稳妥的标准答案框架。**概率分布/Bayesian 表示不是错误，但除非明确说明额外概率假设，它更适合作为后续主动决策层，而不是替代题目给出的硬误差可行集。

### 问题二：第二检测点究竟应该放在哪里

这里是不同网络方案**分歧最大**的地方，而且表面上会看到“30°”和“90°”两个完全不同的答案。

GitHub 方案做的是数值优化，而不是只看经典 GDOP。它报告的推荐区域为：

\[
\boxed{d\simeq1150\text{–}1200\ {\rm m},\qquad |\alpha|\simeq30^\circ}
\]

其中 \(d\) 是从第一次检测点到第二检测点的移动距离，\(\alpha\) 是**相对第一次示向方向的移动偏转角**。其网格优化给出的检测成功率约 **99.7%**，成功取得第二次示向后定位区域直径期望约 **54 m**；一个较宽的近优区域约为

\[
d\in[1000,1300]\ {\rm m},\qquad |\alpha|\in[20^\circ,40^\circ].
\]

作者还测试了不同距离先验，远距离源占比增大时，近优点会向 \(d\approx1300\) m、\(\alpha\approx20^\circ\) 移动。fileciteturn3file0L2-L2

为什么这和很多 CSDN 写的“90°最好”不矛盾？

因为两者说的往往**不是同一个角**。

经典 Bearing-only 定位的误差放大在两条视线接近平行时很差，交会角接近

\[
\beta=90^\circ
\]

通常确实是良好几何构型。因此 GDOP 型方案会写“让两条视线尽可能正交”。CSDN 当前公开题解明确把“接近 90° 的交会角”作为基线。citeturn16search28turn17view0

但从机器人第一测点 \(S_1\) 看，第二测点的**位移方向** \(\alpha\) 并不等于最后由真实目标 \(P\) 看过去的两条视线交会角 \(\beta\)。由于

\[
|S_1P|
\]

未知且位于较大的距离区间，同时第二点还必须尽可能保证进入最小接收半径 1000 m 内，真正优化“检测成功概率 + 新区域大小 + 行驶时间”后，位移方向在 ±30° 左右完全可能产生接近正交的目标视线几何。

因此下列三种网络答案其实对应三种不同优化目标：

| 第二点方法 | 公开推荐 | 优化目标 | 优点 | 主要问题 |
|---|---|---|---|---|
| GitHub 数值优化 | \(d=1150\text{–}1200\) m，\(|\alpha|\approx30°\) | 探测成功 + 新可行区大小 | 有明确 Monte Carlo 数字 | 依赖其自建先验/模拟器 |
| 经典 GDOP | 让**交会角**接近 90°；部分文章把第二点放到首次方向侧方 | 几何条件数 | 简洁、易解释 | 容易把“交会角”和“机器人位移角”混淆 |
| 一步前瞻 minimax | 没有固定 \(d,\alpha\) | 最小化所有可能目标下的最坏 MEC | 最严格、天然适应当前可行集 | 计算较重，也可能过于保守 |

第三种就是 `matlab_dingdang` 的方案。它先构造当前目标可行区域 \(K\)，然后寻找一个第二测点 \(q\)，要求对 \(K\) 中任何潜在目标都能在最坏的 1000 m 接收半径下收到信号。于是候选集合相当于

\[
Q_{\rm safe}
=
\bigcap_{p\in K}B(p,1000).
\]

然后对每个候选 \(q\)，模拟不同真实目标和 ±1° 观测，计算第二次观测后的最小包围圆，并最小化最坏情况。这相当于一步 robust active sensing，而不是预先规定 30° 或 90°。文章明确把近似 90° 交会作为对照基线。citeturn17view0

我认为这其实是问题二最值得写进论文的比较：

\[
\text{GDOP解析基线}
\longrightarrow
\text{期望性能数值优化}
\longrightarrow
\text{minimax鲁棒一步前瞻}.
\]

如果你们最后自己跑模拟器，还可以进一步升级成

\[
q^*
=
\arg\min_q
\left[
\lambda_1E(R_{\rm MEC}^{\rm next})
+
\lambda_2t_{\rm move}(q)
+
\lambda_3P(\text{no signal}\mid q)
\right],
\]

这比简单宣称“最佳角度就是 90°”在数学上完整得多。

### 问题三：全向源的搜索—定位—清除

目前公开方案的层次差距在问题三开始迅速拉开。

**最完整的 GitHub 方案**可以写成：

\[
\boxed{
\text{完备覆盖侦察}
\to
\text{频道级 belief 更新}
\to
\text{交会定位}
\to
\text{保证性清除}
\to
\text{滚动全局调度}
}
\]

它首先要求半径 1000 m 的侦察圆盘**覆盖整个半径 1800 m 目标圆域**。这是一个很重要的鲁棒思想：每个源实际接收半径可能更大，但只用最坏情况下限 1000 m 做完备性证明。定位阶段持续累加 ±1° wedge；`no_signal` 对全向源可作为负几何信息，排除当前测点周围必然无源的部分区域。fileciteturn3file0L2-L2

清除阶段不是“估一个点冲过去”，而有两个 guarantee：

\[
R_{\rm MEC}\le20\ {\rm m}
\]

时走到 MEC 圆心即可保证目标在清除半径内；否则可以用约 33 m 间距的三角格点扫描候选区域，其覆盖半径约 19.05 m，因此同样形成确定性清除证书。fileciteturn3file0L2-L2

更重要的是 v2 的**滚动时域重优化 RHO**。每次收到新观测后，把

\[
\{\text{未访问侦察点}\}
\cup
\{\text{已发现未清除源任务}\}
\]

重新放进一个在线 TSP/任务排序问题，用最近邻初始化并做 2-opt，只执行当前最优路径第一段，然后重新观测、重新规划。这样避免“先扫完整张地图，再返回逐个清除”造成的大量回头路。GitHub 的同种子消融实验声称，Q3 从 **288.8 s/源降到 280.0 s/源**，平均路径从约 14.2 km 降到 13.6 km。fileciteturn3file0L2-L2

其公开 150 局推荐配置实验给出的结果是：

\[
\boxed{\text{Q3 清除率}=100.00\%,\qquad
\bar T=280.0\ {\rm s/source}}
\]

并声称 150/150 局全清，包括“所有源接收半径取下界 1000 m 并贴近外圈”的对抗测试。fileciteturn3file0L2-L2

但这里必须严格标注：

> **280.0 s/源是该作者自建高保真模拟器上的公开成绩，不是经过独立核验的官方模拟器 SOTA。**

仓库公开了与官方接口衔接的 robot 客户端，并按附件中的计时例子做回归，但公开统计主体仍来自自建模拟器。仓库说明中也明确列出了自建模拟、正式运行程序与实验结果文件。fileciteturn3file0L2-L2

**CSDN 集合几何方案**提出了一个更简洁的全向覆盖设计：中心一个点、外围半径约 1150 m 的圆周均匀放置六点，共七点。作者给出几何论证，声称七个半径 1000 m 的检测圆足以覆盖半径 1800 m 的目标区域。它同样维护 20 个频道的动态状态，把 `direction`、`near`、`no_signal` 都作为状态更新；全局扫描和已经发现目标的定位/清除任务之间采用动态优先级，而不是一发现目标立即离开主路线。citeturn17view0

这套方案的优点是**论文非常好写**：七点几何图、覆盖证明、频道状态机、任务优先级都很清晰。但公开页面没有给出像“280 s/源 × 150局 × 固定 seed”这样的逐局公开结果，所以目前不能用它来挑战 GitHub 的数值 benchmark。文章虽然声称依托模拟器和极端场景验证 100% 清除，但没有在公开正文中披露足够详细的时间统计供第三方核查。citeturn17view0

**Bayesian 信息增益路线**则从另一个角度解决问题。小星火公开商品说明显示，它把目标区域栅格化，维护每频道后验概率，构造包含 ±1° 与 `no_signal` 的观测似然，然后做序贯 Bayesian update，并通过**期望信息增益 EIG**决定下一个位置/频道；路径层用最近邻 + 2-opt。其文件列表还明确包含“后验热力图演化”“信息增益曲面”“P3轨迹”“多案例统计”“策略对比”和灵敏度分析。citeturn21view0

这种路线理论上很适合定义

\[
q^*
=
\arg\max_q
\frac{
H[p(x|\mathcal D)]
-
\mathbb E_yH[p(x|\mathcal D,y,q)]
}{
t_{\rm move}+t_{\rm detect}+t_{\rm switch}
},
\]

也就是“**单位时间信息增益**”，而不是单纯“下一次观测最准确”。但它的公开页面没有披露 P3 清除率和秒/源，因此目前只能认定为有价值的**替代建模框架**，不能认定为数值领先。页面在本次抓取时显示浏览 26、已购 0，也没有形成公开社区复现实证。citeturn21view0

**元启发式路线**的小星火商品则明确列出模拟退火、遗传算法、蚁群算法，用于访问顺序和频道调度，并声称同贪心/最近邻 baseline 做统计比较。文件列表确实包含路径优化收敛、箱线图、敏感性、消融和 P3/P4 明细 CSV，但具体实验结果没有在公开页面出现。citeturn21view1

因此“有没有人用元启发式？”答案是**有**；“有没有公开证据证明 SA/GA/ACO 比 RHO+2-opt 更快？”截至本次检索，答案是**没有公开可核验数据**。

我也专门检索了强化学习。截止本次搜索，**没有找到一个明确针对 2026 CUMCM B题、公开代码与实验的 RL/PPO/DQN 方案**。同样没有找到比赛特定的粒子滤波实现。网络上存在无线频谱、干扰定位、无人机观测路径方面的 RL 或 Bayesian 学术研究，但那不能算作本题已公开解法。已有 GNSS 干扰源无人机定位路径规划论文可作为学术背景参考，但问题设置和 CUMCM B 的 HTTP/频道/清除规则不同。citeturn16search7

### 问题四：定向干扰源为什么不是“多扫几个点”那么简单

问题四的核心不是定位算法本身，而是**可观测性**。

假设一个定向源在位置 \(p\)，有效方向为某单位向量 \(u\)，信号覆盖一个 180° 半平面。一个在接收半径内的侦察点 \(q_i\) 能收到信号，需要满足类似

\[
u^\top(q_i-p)\ge0.
\]

如果所有距离 \(p\le1000\) m 的搜索点都落在 \(p\) 的某一个开半平面内，那么存在一个朝向 \(u\)，使它们全部位于发射背面——此时源会**永久隐身**。

因此 GitHub 方案提出比“1000m 圆覆盖”更强的**环绕条件**：

\[
\boxed{
p\in
\operatorname{conv}
\{q_i:\|q_i-p\|\le1000\}
}
\]

即对区域中任意潜在源位置，其 1000 m 内的侦察点必须从方向上包围它。这样就不存在一个经过 \(p\) 的半平面把所有这些侦察点同时放在发射盲区。仓库使用了一个 19 点环绕侦察集。fileciteturn3file0L2-L2

它在此基础上做了一个非常值得借鉴的 v2 改进：**定向源朝向 Bayesian belief**。

对每个频道不仅维护

\[
p(x),
\]

而是维护位置—方向联合状态

\[
p(x,u|\mathcal D),
\]

其中朝向按约 5° 分箱。尤其重要的是，它不再把定向源的 `no_signal` 简单解释为“这里没有源”，而是利用负观测更新朝向可能性。得到 \((\hat p,\hat u)\) 后，策略主动移动到估计前向一侧，例如仓库的思路近似为

\[
q_{\rm next}
=
\hat p+350\,\hat u,
\]

从“被动围着目标瞎扫”变成“推断它朝哪，然后主动绕到正面”。fileciteturn3file0L2-L2

该改进公开消融声称 Q4 从约 **536.0 s/源降到 504.1 s/源**，请求数从约 360 降至 287；相对于完整 v1，Q4 从 **574.4 s/源降到 504.1 s/源**，平均路径约 27.6 km→24.0 km，请求 357→287。推荐配置的 150 局报告为：

\[
\boxed{
\text{Q4 清除率}=100.00\%,\qquad
\bar T=504.1\ {\rm s/source}
}
\]

同样，这依然是**自建模拟器 benchmark，不是官方 SOTA**。fileciteturn3file0L2-L2

更有价值的是作者没有停在 150 局。他们还公开做了 \(N=10,\ldots,20\) 与不同全向/定向配比的系统性测试。当前 README 汇总称总计 **1980 局、29,700 个干扰源**；其中 1650 局混合测试的清除比例为 **99.923%（24,731/24,750）**，1631/1650 局全清，所有 19 个漏检都来自定向源；全向源 12,360 个则全部被清除。fileciteturn3file0L2-L2 其测试配置包括目标位置圆域均匀、接收半径 \(R\sim U(1000,1500)\)、示向误差 \(|\epsilon|\le1^\circ\) 和固定随机种子。fileciteturn5file8L110-L112

这也揭示了一个很重要的事实：

> **“150 局 100%”不能等价于“算法具有全局 100% 数学保证”。**

其更大规模压力测试仍出现了少量定向源几何盲区。这反而使这份仓库比很多只写“100%成功”的营销题解可信，因为它公开了失败案例。

CSDN 的另一套方案从纯几何角度解决同一问题：使用边长约 **900–950 m 的等边三角网格**，甚至允许部分侦察点落在目标圆外。要求每个源都落在三个近邻搜索点形成的三角形凸包中，而且三个点到目标均不超过 1000 m。由于目标在这三个观测点的凸包内，任何 180° 发射半平面都无法把三个点同时排除，因此至少一个会收到信号。citeturn17view0

本质上，

\[
\text{三角格点方案}
\]

是 GitHub

\[
\text{convex-hull surround condition}
\]

的一个构造性充分条件。两者在数学思想上其实高度一致。

相比之下，一些普通网络讲解只建议“围着源从 90°、180° 不同方向多试几个点”“螺旋搜索”“四个方向探测”。这可以提高经验成功率，却没有给出“对于任意未知朝向一定至少有一次可见”的几何证明，因此论文中最好不要把它表述成 100% 保证。

## 主流思路与少数派思路

目前真正形成“共识”的第一条，是**确定性集合定位，而不是点估计**。

只要测向误差解释成

\[
|\epsilon|\le1^\circ,
\]

一次正检测产生的就是一个 2° wedge；两次以上观测得到 wedge intersection。GitHub 和当前较完整的 CSDN 题解都采用这一框架。citeturn17view0 这应该算问题一最接近“标准路径”的东西。

第二条共识是：**直径负责回答题目要求，MEC负责清除保证。**

\[
D(K)\le40
\]

不是可靠的清除证书；

\[
R_{\rm MEC}(K)\le20
\]

才是。GitHub 还给出了 Jung 上界、显式反例和随机覆盖率，因此这里已经不太存在合理争议。fileciteturn3file0L2-L2

第三条共识是问题二应该追求**横向基线**，避免近共线交会。争议的只是如何定义“最佳”：GDOP 派说近 90° 交会；数值派给出从第一点位移约 1150–1200 m、偏约 30°；robust 派则根本不固定角度，而实时解一步 minimax。citeturn17view0 fileciteturn3file0L2-L2

第四条共识是问题三必须同时解决两件看似冲突的事：

\[
\text{全域完备侦察}
\qquad\text{和}\qquad
\text{尽早插入已发现源的定位/清除}.
\]

只做前者会产生大量回头路；只做后者则可能一直追踪一个源而失去全局完备性。因此“覆盖路线 + 在线插序/RHO”明显比简单的“扫完再清除”成熟。GitHub 与 CSDN 的动态任务方案都体现了这一趋势。citeturn17view0

第五条共识是问题四需要**方向覆盖几何条件**，单纯“距离覆盖”不足：

\[
B(p,1000)\text{ 内有检测点}
\]

不够，最好进一步满足

\[
p\in\operatorname{conv} Q_p.
\]

GitHub 称其为环绕条件，CSDN 三角网格是它的构造性实现。citeturn17view0 fileciteturn3file0L2-L2

相对少数派但很有潜力的方向则有四类。

**Bayesian 信息增益**没有把下一个测点简化成固定规则，而是真正把“下一次观测能减少多少不确定性”量化。小星火商品页明确采用 posterior、观测 likelihood、序贯 Bayesian update 和 expected information gain，并做位置—频道联合决策。citeturn21view0

**位置—朝向联合 belief**目前在公开资料中更稀有。GitHub 对定向源把 `no_signal` 用作朝向反证，是目前我看到的比较有实质性的 P4 创新之一，而不仅仅是“多绕几圈”。fileciteturn3file0L2-L2

**风险可控的自适应覆盖**也是少数派。它不一定把每个最坏情形都覆盖到，而是估计遗漏风险，再决定是否值得省掉某些侦察点。这适合拿来画 Pareto 曲线，但如果最终评分对漏源惩罚极重，默认策略仍应回到严格覆盖。fileciteturn3file0L2-L2

**SA/GA/ACO 等元启发式**公开方案确实存在，但从本题在线性质看，我认为其价值更多在“离线寻找较好的侦察顺序/参数”而不是每次观测后从头跑大规模遗传算法。小星火对应方案明确把这些算法用于访问顺序和频道调度，并配置了贪心/最近邻 baseline。citeturn21view1

目前反而**没有**形成公开比赛方案的是 RL、粒子滤波和真正的 POMDP solver。它们从理论上当然适合这个问题：

\[
b_{t+1}(s)\propto
P(y_t|s,a_t)b_t(s),
\]

\[
a_t^*=
\arg\min_\pi
E[T_{\rm all\ clear}],
\]

但 72 小时国赛场景中，训练环境真实性、策略可解释性、最坏情况下清除保证和论文篇幅都会成为现实障碍。除非已经有成熟训练框架，否则“为了创新强上 PPO”未必优于几何证书 + Bayesian belief + rolling horizon。

## 推荐参考优先级

**第一优先：GitHub `li2396803/cumcm2026-b-radio-interference-localization`。**

这是目前明显最值得深入拆解的一份。不是因为它标题最夸张，而是因为它公开了从几何引擎、自建模拟器、策略、官方接口客户端、实验脚本、150 局对照到更大规模 sweep 的完整链条，而且明确给出了失败统计，而不只展示成功案例。当前 README 报告 Q3 100% / 280.0 s/源、Q4 100% / 504.1 s/源，同时还有 v1→v2 消融和 1980 局压力测试。fileciteturn3file0L2-L2

它最值得抄的不是最终数字，而是论文结构：

\[
\text{几何定理}
\to
\text{完备性条件}
\to
\text{算法}
\to
\text{自建模拟器}
\to
\text{消融}
\to

这正是高水平数学建模论文应有的证据链。

**第二优先：CSDN `matlab_dingdang` 的集合感知/七点覆盖/三角网格方案。**

它在理论叙述上甚至比很多付费“完整论文”更干净：明确反对无根据的 Gaussian 点估计，使用 set-membership；问题二提出 strong-safe candidate + one-step minimax；问题三给七点覆盖结构；问题四用 900–950 m 三角网格构造方向鲁棒覆盖。citeturn17view0

\text{expected-case optimization}
\quad\text{vs}\quad
\text{worst-case robust optimization}.
\]

论文可以同时写两者，再通过官方/自建仿真决定最终策略。

**第三优先：小星火 Bayesian 信息增益方案，只参考思想，不直接相信结果。**

公开说明包含位置栅格后验、±1°/无信号 likelihood、序贯更新、EIG、位置—频道联合决策和 NN+2-opt，文件目录也显示包含后验热力图、熵下降、策略比较、P4 定向源后验和灵敏度。citeturn21view0

它最值得借鉴的是把本题从“计算几何题”提升为一个简化版的

\[

\]

问题。但由于公开页没有披露关键秒数和清除率，不能把它的营销性“完整结果”当作独立验证。

**第四优先：小星火元启发式方案。**

它至少证明当前网络上确实有人把 P3/P4 建模成路径+频道联合优化，并尝试 SA/GA/ACO，而不是所有人都停在 greedy。页面列出了正式的策略对比、收敛曲线、箱线图、敏感性和消融文件。citeturn21view1

\text{正式三次/规定次数测试日志}
+
\text{随机场景信息}
+
\text{清除率}
+
\text{秒/源}
+
\text{代码}.
\]

所以现在谁说“官方 SOTA 220 s/源”或“已经国一”，都需要对方先给官方运行日志。当前最强的 **280.0 / 504.1** 只能称为：

\[
\boxed{\text{公开、可复现、自建模拟器 claimed benchmark}}
\]

而不能称为官方 SOTA。fileciteturn3file0L2-L2

第二个缺口是**误差的统计结构**。题面给的是 ±1° 边界，但很多 Bayesian/Monte Carlo 算法为了模拟会进一步假设

\[
\epsilon\sim U[-1^\circ,1^\circ]
\]

或者某种固定位置伪随机误差场。GitHub 的系统测试就明确使用了位置相关的确定性伪随机误差场并保持 \(|\epsilon|\le1^\circ\)。fileciteturn5file8L110-L112 如果真实官方模拟器的误差具有空间相关性，那么“同一点反复测很多次取平均”可能根本不像独立噪声那样收敛。这个问题目前多数商业题解讨论不足。

第三个争议是问题二所谓“最佳 \((d,\alpha)\)”其实**没有脱离目标函数的绝对答案**。

若目标是最大化局部 GDOP：

\[
\beta\approx90^\circ.
\]

若目标是最小化平均新定位区域：

\[
(d,\alpha)\approx(1150\text{–}1200\,{\rm m},30^\circ)
\]

是当前公开 Monte Carlo 的一个强结果。fileciteturn3file0L2-L2

若目标是任何目标位置都必须收到第二次信号并最小化最坏 MEC，就应该解 CSDN 那样的 robust minimax，而未必得到固定的 \((d,\alpha)\)。citeturn17view0

因此论文中最专业的表述不是“经证明第二点必须为 30°”，而是：

> 在给定先验、接收模型和期望型目标函数下，数值搜索得到约 \(1150\text{–}1200\) m、30° 的近优区域；90°指的是理想视线交会角而非必然等同于机器人位移角；若采用最坏情形准则，最优点需随当前可行域在线求解。

第四个缺口是 P4 的**边界环绕证明和有限点集设计**。理论上 convex-hull condition 很漂亮，但实际有限个搜索点在圆域边缘、1000 m 距离截断处可能出现小空隙。GitHub 150 局达到 100%，但扩大到近三万源后所有 19 个漏检都来自定向源，这恰恰表明“理论条件正确”不等于“你设计的离散点集处处满足理论条件”。fileciteturn3file0L2-L2

这可能是当前最值得继续优化的地方：不要只是随机仿真侦察点集，而直接求

\[
\max_{p\in\Omega}
\mathbf 1
\left[
p\notin
\operatorname{conv}
\{q_i:\|q_i-p\|\le1000\}
\right]
\]

是否为零，或者计算一个**环绕裕量**，再优化点集。这个方向比单纯加几个侦察点更有数学含量。

第五个缺口是“频道价值”的联合优化。目前大部分几何解法重点决定“去哪”，Bayesian 商业方案已经开始同时决定“去哪 + 测哪个频道”。citeturn21view0 由于换频道需要额外时间，真正的决策对象应当是

\[
a=(q,c),
\]

目标类似

\[
a^*
=
\arg\max_{q,c}
\frac{
\text{expected uncertainty reduction}
+
\text{clearance probability gain}
}{
t_{\rm move}+t_{\rm measure}+t_{\rm switch}
}.
\]

这很可能是一个仍有明显提升空间的方向。

第六个缺口是**清除与搜索的统一价值函数**。很多方案先定位到足够精确再清除，但实际未必需要把位置估到一个“漂亮坐标”。本题最终只需要进入 20 m：

\[
\exists q:
K\subseteq B(q,20).
\]

因此最自然的 belief metric 其实不是坐标 RMSE，也不一定是直径，而是

\[
R_{\rm MEC}(K)
\]

以及“再采取一个动作后 \(R_{\rm MEC}\le20\) 的概率”。CSDN 和 GitHub 已经意识到 MEC 的作用，但公开方案中把它真正纳入主动测量 utility 的还不多。citeturn17view0

第七个问题是**网络来源并不真正独立**。短时间内出现的大量 CSDN、技术站、B站、“论文代码包”页面往往采用高度相似的“楔形—GDOP—覆盖—路径优化”叙事，有的还互相转载。因此不能因为搜到十篇都写“旋转卡壳+90°”就理解成十支队伍独立验证了它。当前赛题发布时间只有几天，公开社区还远没有形成经同行复现的成熟共识。citeturn23view0turn16search28

综合本轮调查，我认为现在最稳妥的技术路线可以浓缩为：

\[
\boxed{
\begin{aligned}
&\textbf{P1: }
\text{Set-membership wedge intersection}
+\text{rotating calipers}
+\text{MEC};\\[2mm]
&\textbf{P2: }
\text{GDOP作解析基线}
+\text{Monte Carlo / minimax主动选点};\\[2mm]
&\textbf{P3: }
\text{严格1000m覆盖}
+\text{NO\_SIGNAL剪枝}
+\text{在线插序/RHO}
+\text{保证性清除};\\[2mm]
&\textbf{P4: }
\text{convex-hull surround}
+\text{orientation belief}
+\text{主动绕前向侧观测}.
\end{aligned}}
\]

其中目前真正有公开数字可作为竞争目标的是：

\[
\boxed{
\text{Q3：100\% clear,\ 280.0 s/source}
}
\]

和

\[
\boxed{
\text{Q4：100\% clear,\ 504.1 s/source}
}
\]

但二者必须始终带上 **“150 局、自建高保真模拟器、公开项目自报”** 这个限定。更大的压力测试已经显示 Q4 并非真正无条件 100%，因此当前最值得超过的不只是 504.1 秒，而是：

\[
\boxed{
\text{在严格环绕/对抗场景中仍保持接近100\%清除，
同时把时间压到500s以下}
}
\]
